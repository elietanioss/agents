=== TECHNOLOGY STACK ===
Frontend: React (react-dom confirmed in bundle) + React Router + Redux Toolkit, built with Vite (hashed asset filenames e.g. index-sxBIrYLU.js/css), client-side-rendered SPA with a boot/loading screen and PWA manifest (manifest.webmanifest, apple-touch-icon, theme-color #0D3B66)
Libraries observed in bundle: jsPDF (client-side PDF generation), Amplitude (product analytics), Google Maps embed, wa.me (WhatsApp deep links)
Payment integration: "Whish" string confirmed present in bundle (matches known payment processor per engagement scope - out of scope, not tested); a "stripe" string reference was also observed - unclear if active/secondary processor or unused dependency remnant, flagged as a hypothesis only, not confirmed by active testing
Backend: reverse-proxied API under /api/* on the same domain (confirmed via /api/health -> HTTP 200 {"ok":true}, application/json; distinct 404 text/plain behavior for unmapped /api/* sub-paths e.g. /api/v1, /api/auth, /api/users, /api/docs, /api/swagger, /api/version, /api/status). No version/framework banner disclosed for the backend.
CORS: /api/health does NOT reflect Access-Control-Allow-Origin for an arbitrary cross-origin Origin header (tested with https://evil.example.com) - properly restrictive, positive control.
Cookies: none set on initial GET of / (no session cookie leaked pre-auth); app likely uses token-based auth via JS, not verified further (out of scope for recon).
Edge/CDN: Cloudflare (server: cloudflare on all responses; cf-ray present; Cloudflare-managed robots.txt content-signal block present, opting out of AI training crawlers while allowing search indexing)
Security headers (main app, zakerne.com & www.zakerne.com): Content-Security-Policy (self-hosted, no unsafe-inline for scripts), Strict-Transport-Security (max-age=31536000; includeSubDomains; preload), X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Permissions-Policy (camera/mic/geo denied), Referrer-Policy: strict-origin-when-cross-origin -- solid baseline, no findings against the main app's header set.
Security headers (security.zakerne.com): MISSING the entire baseline above (no CSP/HSTS/X-Frame-Options/X-Content-Type-Options/Permissions-Policy) - see findings.
No API keys, tokens, or private-key material found in a passive grep of the main JS bundle (checked for sk_live_/sk_test_/AIza.../AKIA.../pk_live_/pk_test_/PEM private key patterns - none found).

Directory/file discovery caveat: ffuf against raft-medium-files.txt produced ~2995 apparent "200 OK" hits, but this is a FALSE-POSITIVE artifact of the SPA's catch-all client-side routing (the server returns the same 4250-byte index.html shell with HTTP 200 for effectively any unmapped path, e.g. /login2.php, /.env, /.git/config all return the identical SPA shell). Traditional wordlist-based directory brute forcing is unreliable against this app architecture; targeted path probing (e.g. checking for distinct response size/content-type/status) was used instead and is the recommended technique for the pentest-web phase.

=== TLS/SSL ===
Certificate: valid, CN=zakerne.com, SAN covers zakerne.com/security.zakerne.com/*.security.zakerne.com, issued by Google Trust Services, expires 2026-09-26 (72 days remaining at scan time - OK), SHA256 signature, RSA 2048-bit key, no OCSP stapling, Certificate Transparency present.
Issues found:
  - TLS 1.0 and TLS 1.1 offered/accepted (deprecated) - MEDIUM (see finding-recon-20260716T171825Z-tls-legacy-protocols.json)
  - 3DES/IDEA (64-bit block cipher) offered -> SWEET32 VULNERABLE (CVE-2016-2183) - MEDIUM, same finding as above
  - BEAST (CVE-2011-3389): TLS1 CBC ciphers offered but likely mitigated since TLS1.2 also available - noted, folded into same finding
  - TLS 1.3 NOT offered (unusual for Cloudflare defaults; likely a side effect of the legacy-compatible cipher/minimum-TLS configuration) - noted in same finding
  - No CAA DNS record - LOW/INFO (see finding-recon-20260716T171825Z-missing-caa-record.json)
  - Heartbleed, CCS, Ticketbleed, ROBOT, CRIME, POODLE, FREAK, DROWN, LOGJAM: all NOT VULNERABLE (OK)
  - Secure Renegotiation: supported (OK); TLS_FALLBACK_SCSV: supported (OK)

=== HANDOFF NOTES FOR pentest-web ===
- Real backend API confirmed at /api/* on zakerne.com (proxied through Cloudflare); /api/health is a safe, confirmed-live reference endpoint to validate connectivity/auth flows against.
- Do NOT rely on raw wordlist directory brute forcing against this target - SPA catch-all routing returns false-positive 200s for almost any path. Use response-size/content-type differentials or targeted, framework-aware path lists (React/Vite + REST API under /api/*) instead.
- security.zakerne.com is a separate first-party SPA ("Zakerne security monitoring dashboard") covered by the same TLS cert - in scope, but verify with the orchestrator whether this is the client's OWN existing security-monitoring tool (RoE mentions "another security team monitoring the site") before treating it as a standard test target, to avoid duplicate/conflicting activity.
- Payment flows: Whish integration confirmed in bundle; a "stripe" string was also observed and is unconfirmed/unexplained - do not interact with either beyond passive/GET-level fingerprinting per RoE constraint on cost-incurring actions.
- No origin-IP-bypass vector identified; Cloudflare enforcement appears intact based on DNS/header inspection only (not actively validated by attempting a bypass, per RoE).
